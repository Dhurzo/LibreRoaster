# Milestone v2.6: Problemas que impiden funcionamiento real en hardware

**Status:** ✅ SHIPPED 2026-02-18
**Phases:** 46-48
**Total Plans:** 10

## Overview

v2.6 Problemas que impiden funcionamiento real en hardware makes the SSR/fan loops deterministically drive LEDC timers and turns the UART/USB transports into embassy-friendly futures so Artisan commands reach the hardware without introducing executor stalls.

## Phases

### Phase 46: SSR Reliability Foundation

**Goal**: Users observe that SSR commands always map to the correct LEDC duty, honor the datasheet cycle time, and trigger retries/logs when the applied duty drifts.
**Depends on**: None (foundation)
**Plans**: 3 plans

Plans:

- [x] 46-01-PLAN.md — saturating duty math, guard/tolerance constants, and helper tests in `hardware::ssr`
- [x] 46-02-PLAN.md — cycle-guard scheduler plus `RoasterControl` gating and scheduler tests
- [x] 46-03-PLAN.md — LEDC drift monitor/retries, telemetry fields, and TEST-01 verification doc

**Details:**
- SSR saturating duty math (0-100% → LEDC 0-255)
- Cycle guard enforcement (≥1 second)
- LEDC drift monitoring (±2 ticks) with retry
- Telemetry fields: ssr_last_duty_delta_ticks, ssr_retry_count, ssr_cycle_guard_busy_until_ms

---

### Phase 47: Deterministic Fan Control

**Goal**: Users see FanController commands write directly to the LEDC channel and avoid collisions or audible jumps by serializing updates (with optional fades).
**Depends on**: Phase 46
**Plans**: 2 plans

Plans:

- [x] 47-01-PLAN.md — build the shared LEDC bus, move `FanController` onto it, and initialize the serializer in `main.rs`
- [x] 47-02-PLAN.md — bring SSR control and RoasterControl telemetry onto the bus and add serialization tests

**Details:**
- FanController wired to shared LedcBus
- Serialized LEDC writes via atomic guard
- Fan telemetry reflects applied duty (not requested value)
- Optional fan fades for smooth transitions

---

### Phase 48: Async Transport Resilience

**Goal**: Users flood UART or USB CDC and still see responsive Artisan command handling because transports run as embassy futures with back-pressure awareness.
**Depends on**: Phase 47
**Plans**: 5 plans

Plans:

- [x] 48-01-PLAN.md — Convert UART to async with embassy traits and buffered event queues
- [x] 48-02-PLAN.md — Add back-pressure awareness to USB CDC channel
- [x] 48-03-PLAN.md — Implement FIFO command queue with reject-on-full behavior
- [x] 48-04-PLAN.md — Create integration flood tests for TEST-02
- [x] 48-05-PLAN.md — Wire CommandQueue to artisan_channel (gap closure)

**Details:**
- Async UART with embassy embedded_io_async
- USB CDC back-pressure with exponential backoff (1ms→10ms)
- CommandQueue with heapless::Deque, FIFO reject-on-full
- Queue processor tasks: queue_processor_task (UART), usb_queue_processor_task (USB)
- Full E2E command flow: UART/USB → queue → channel → control → LEDC

---

## Milestone Summary

**Key Decisions:**

- Shared LedcBus with atomic guard serializes SSR and Fan LEDC writes
- Embassy async transports prevent executor stalls under load
- CommandQueue provides FIFO semantics with back-pressure

**Issues Resolved:**

- SSR double-division duty calculation fixed
- FanController now drives physical LEDC channels
- UART/USB drivers no longer block the executor

**Issues Deferred:**

- Hardware verification (TEST-01) requires physical ESP32-C3 board
- SSR telemetry not consumed by fan control (future enhancement)

**Technical Debt Incurred:**

- Dead code warnings in uart/tasks.rs (handle_complete_command, send_parse_error)
- Mutable static warnings (already wrapped in critical_section::with)
