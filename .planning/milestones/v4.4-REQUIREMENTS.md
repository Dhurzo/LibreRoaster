# Requirements: LibreRoaster v4.4

**Defined:** 2026-02-24
**Core Value:** Artisan can read temperatures and control heater/fan during a roast session via serial connection.

## v1 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### SSR Refactoring

- [x] **SSR-01**: Extract common state into `SsrControlBase` struct with fields shared between `SsrControl` and `SsrControlSimple` (hardware_status, current_duty, last_duty_delta_ticks, retry_count, last_detection_check, is_pwm_enabled)
- [x] **SSR-02**: Define `SsrControlTrait` with default implementations for common methods (detect_heat_source, periodic_check, getters for hardware_status, is_heating_available, get_current_duty)
- [x] **SSR-03**: Refactor `SsrControl` to embed `SsrControlBase` and implement `SsrControlTrait`, delegating all common methods
- [x] **SSR-04**: Refactor `SsrControlSimple` to embed `SsrControlBase` and implement `SsrControlTrait`, delegating all common methods
- [x] **SSR-05**: Verify all existing tests pass after refactoring; ensure no regression in heater control behavior

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Dynamic dispatch (`dyn SsrControlTrait`) in hot paths | Adds runtime cost; embedded Rust prefers static dispatch |
| External mock crates (mockall, faux) | Adds build complexity; manual stubs are sufficient |
| PID control implementation | Already exists in RoasterControl; this is refactoring |
| HIL test setup | Requires hardware; defer to future milestone |
| Property-based testing | Adds proptest dependency; manual tests sufficient for v1 |
