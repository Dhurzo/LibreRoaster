  <name>Task 1: Implement `SsrCycleGuard` module</name>
  <files>src/control/ssr_scheduler.rs, src/control/mod.rs</files>
  <action>
Create `src/control/ssr_scheduler.rs` with a `SsrCycleGuard` that stores `Option<Instant>` for the last cycle and a `Duration` derived from `SSR_CYCLE_GUARD_MS`. Provide APIs:
1. `fn next_cycle_allowed(&self, now: Instant) -> Result<Instant, Instant>` that returns `Ok(now)` when free or `Err(busy_until)` when the guard is still active.
2. `fn mark_cycle(&mut self, now: Instant)` to record the command that kicks off a cycle.
3. `fn busy_until(&self) -> Instant` helper used by telemetry/logging.

Add module-level tests in `tests/ssr_scheduler.rs` (see Task 3) and re-export the module via `src/control/mod.rs` so `RoasterControl` can instantiate the guard.
  </action>
  <verify>cargo test --test ssr_scheduler</verify>
  <done>`SsrCycleGuard` exposes the timing APIs, uses `SSR_CYCLE_GUARD_MS` for durations, and the module is exported from `control::mod`. Internal tests cover the timing logic.</done>
</task>

<task type="auto">
  <name>Task 2: Gate RoasterControl heater updates with the guard</name>
  <files>src/control/roaster_refactored.rs</files>
  <action>
Add an `ssr_guard: SsrCycleGuard` field to `RoasterControl` (initialized in `new`). Extend `SystemStatus` with a `u64` field (e.g., `ssr_cycle_guard_busy_until_ms`) to hold `busy_until.duration_since(Instant::now()).as_millis()` so telemetry shares the busy window without storing `Instant`.

Update `apply_manual_heater`, PID updates, and `update_control` so they call `guard.next_cycle_allowed(now)` before `heater.set_power`. When the guard is busy, skip the command, log `warn!("SSR cycle busy until {:?}")`, and store the future timestamp in the status field so Artisan clients can observe the busy window. When a cycle is marked, call `guard.mark_cycle(now)` and write the actual duty only when allowed.
  </action>
  <verify>cargo test --test ssr_scheduler</verify>
  <done>Manual/PID heater paths consult the guard and leave `SystemStatus::ssr_cycle_guard_busy_until_ms` set whenever SSR-02 delays a command.</done>
</task>

<task type="auto">
  <name>Task 3: Add guard timing regression tests</name>
  <files>tests/ssr_scheduler.rs</files>
  <action>
Implement tests that simulate `Instant::from_micros` values to assert:
1. The guard allows a new cycle once 1 000 ms elapses.
2. Commands issued before the guard expires return `Err(busy_until)` showing the expected future timestamp.
3. `mark_cycle` updates the next allowed window, and `busy_until()` returns the same timestamp.

Use `embassy_time::Instant::from_micros` or a helper `Instant::from_millis` shim so tests run on the host target.
  </action>
  <verify>cargo test --test ssr_scheduler</verify>
  <done>Regression tests fail if the guard allows cycles sooner than 1 second or reports the wrong busy-until time.</done>
