  <name>Task 1: Make validation runner manifest-aware</name>
  <files>tests/hardware/validation_runner.py</files>
  <action>
    Extend the runner to:
    1. Accept --manifest (default tests/hardware/scenario_manifest.json), --scenario (one of the manifest IDs or "all"), --runs-dir (default tests/hardware/runs), and --metadata-suffix (default .json).
    2. Load the manifest to know which scenarios are available, their command_sequence, expected_columns, and golden_output paths.
    3. For each polling loop, bundle STATUS telemetry into tests/hardware/runs/{scenario_id}/{timestamp}/telemetry.csv and write adjacent metadata JSON that records run_id, scenario_id, manifest entry, and max_command_latency_us.
    4. Create the target directory tree before writing so auditors can find artifacts under tests/hardware/runs/{scenario_id}/{timestamp}/.
    Why: Without manifest awareness, the runner cannot prove which scenario produced a CSV, so analysis cannot match it to golden outputs.
  </action>

  <done>validation_runner now exposes manifest-aware CLI flags, writes per-scenario run directories, and records metadata JSON alongside each CSV.</done>

  <files>tests/hardware/analysis.py</files>
  <action>
